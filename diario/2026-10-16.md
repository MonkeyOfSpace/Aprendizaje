- **Workflow vs agente, afinado.** Primera respuesta de Jorge: "agente = LLM + herramientas + memoria". Eso es el *augmented LLM*, el ladrillo; un workflow también lo tiene. Segunda aproximación suya: "lo que define al agente es la evaluación de la condición de éxito". Casi: lo que lo define es **quién** la evalúa. En el workflow la evalúa el código (contador, `if`); en el agente la evalúa el modelo paso a paso, mirando el último resultado. En la API eso es literalmente el campo `stop_reason`: `"tool_use"` significa "aún no he acabado", `"end_turn"` significa "ya está". El loop de un agente, en esencia, es `while stop_reason == "tool_use"`: el `while` lo escribes tú, la condición la rellena el modelo. El harness añade un freno (máximo de iteraciones, confirmación humana).
- **Aplicado:** Claude Code es un agente envuelto en trozos de workflow (el protocolo de `CLAUDE.md`, el modo plan, los hooks). Jorgharness en la semana 2 (una llamada con una herramienta) no será un agente, igual que el parser de Aircall con Haiku; en la semana 3, con el `while`, sí.
- **Patrón a vigilar:** el loop se le escapó ayer en el README y hoy en la definición. Es invisible desde fuera; es el concepto a clavar esta semana.
- **Tool use como contrato.** Empezado, no terminado: una herramienta para la API es `name` + `description` + `input_schema`. El modelo nunca ve el código, solo rellena el formulario. Es una definición de requisitos.
