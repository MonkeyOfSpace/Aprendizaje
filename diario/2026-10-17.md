## Qué hemos visto

- **Reflexión de la Fase 0, retocada y cerrada.** Jorge añadió la línea del *augmented LLM* antes de la lista de piezas y la frase "los agentes deciden cada paso mirando el resultado del anterior". Pendiente para la nota de la Fase 1: fundir "decide todos los pasos" con esa frase en una sola.
- **`AGENTS.md` resuelto.** Jorge desactivó la sincronización de agentes externos en la app de Codex y borró el fichero. No hace falta tocar el `.gitignore`.
- **Tool use como contrato, reconstruido entero.** Ficha real de la herramienta `Read` de Claude Code y el JSON de ida y vuelta de una llamada con herramienta (petición, bloque `tool_use`, `tool_result`). La `description` es lo único que el modelo lee para decidir si usa la herramienta.
- **La descripción de `leer_fichero`, en tres iteraciones de Jorge.** Primera: "úsala solo si no tienes ya la respuesta". Error conceptual: deja la decisión en lo que el modelo *cree* saber, y ante "¿qué dice el README?" puede inventarse uno. El disparador tiene que anclarse en algo observable de la petición (criterio de aceptación verificable, no "cuando el dev se sienta seguro"). Segunda: anclada en la petición, sin el "cuándo no". Tercera: completa, con "cuándo no", regla de ruta relativa y qué devuelve. Dos errores de contrato que Jorge cometió y que son la lección: copiar la descripción de `Read` (ruta absoluta, 2000 líneas) para una herramienta que no tiene esos parámetros, y `required: ["file_path"]` con el parámetro llamado `ruta`.
- **La skill `claude-api`, mostrada por dentro.** Un `SKILL.md` de unas 400 líneas con tabla de modelos y precios, más carpetas por lenguaje que se leen bajo demanda (progressive disclosure, Fase 2). Recomienda el *tool runner* del SDK; nosotros hacemos el loop a mano a propósito.
- **Decisión de modelo: Haiku 5.5** (`claude-haiku-5-5`, 0,10 $/M entrada, 0,50 $/M salida), en una constante para cambiarlo en una línea.
- **Lectura de la respuesta bloque a bloque**, dos ejecuciones:
  - "¿Qué dice el README?" → `stop_reason: "tool_use"`, un solo bloque `tool_use` con `input: {"ruta": "README.md"}`, 0 tokens de razonamiento, 54 de salida.
  - "Explícame qué es un harness" → bloque `thinking` (texto vacío, `signature` cifrada, 157 tokens cobrados) + bloque `text`. En la ejecución de Jorge, `stop_reason: "max_tokens"`: Haiku llegó a los 1024 tokens del script y la API lo cortó a media frase. Tercer `stop_reason` visto en vivo, y el primer freno del harness que hemos tocado.
  - Mismo prompt, respuestas distintas entre la ejecución mía y la de Jorge: el modelo no es determinista.
  - 517 tokens de entrada en ambas: casi todo es la ficha de la herramienta, que se paga en cada llamada aunque no se use (Fase 2).
- **El nudo de la semana, con tropiezo y corrección.** Jorge escribió que "la API devuelve el resultado del tool use". No: la API nunca ejecuta nada; devuelve un bloque `content` con la herramienta que quiere usar y los parámetros rellenos. Es una petición. Al README no le pasó nada: nadie lo leyó, y en el script ni siquiera existe una función `leer_fichero`, solo la ficha. Lo que falta para ser agente: ejecutar la función con el `input`, devolver `tool_result` con el mismo `id`, y volver a llamar mientras `stop_reason == "tool_use"`. Frase final de Jorge, correcta: "lo que la API devuelve es un bloque content con la herramienta que quiere usar y los parámetros necesarios para usarla".
